01_GAME_BACKEND

TypeScript / Strapi / PostgreSQL / Socket.IO

A data-driven backend for an online card game. Strapi models game entities and relationships, while custom TypeScript logic coordinates battle turns and pushes battle-state events to connected players.

/01

Game-state orchestration

BattleManager starts battles, processes skill use, updates cooldowns, checks win/loss conditions, and emits results.

/02

Composable combat mechanics

Skill data references mechanics for damage, healing, and targeting, separating configurable game content from turn-processing code.

/03

Typed content model

Character and skill content types use TypeScript definitions and Strapi schemas, with reusable mechanic components.

FILE: backend/scripts/BattleManager.ts
// Battle lifecycle: server-side orchestration
Start() {
  this.player1.socket.emit("startbattle", {
    left: JSON.stringify(this.player1, BlackList),
    right: JSON.stringify(this.player2, BlackList)
  });
  // Player two receives reversed perspective

02_SYSTEM_ARCHITECTURE

A repository-grounded view of the backend layers and how they work together.

01 / Data & Admin

Strapi + PostgreSQL

Strapi provides content management and API structure. PostgreSQL is configured as the relational database using environment-based connection settings.

02 / Game Logic

TypeScript services

BattleManager coordinates battle flow and turn resolution. Mechanics and targeting types model effects such as damage and healing.

03 / Client Updates

Socket.IO events

Connected players receive battle-start, turn-result, and game-over messages with player-relative state payloads.
